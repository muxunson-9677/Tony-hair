# Tony宝 V4 第①步：记忆继承、归因与品牌升级总设计

> 设计日期：2026-08-12  
> 实施基线：`88c15d7fe3d105ba15be4bcfc74b13b49b2f7444`（`codex/decision-assistant`）  
> 设计分支：`codex/v4-step1-memory-brand`  
> 产品版本：`0.1.0`  
> 状态：待产品负责人审阅；本文确认前不修改产品代码

## 1. 目标与成功定义

本轮只完成 V4 路线图第①步：

1. 让已有的满意经验、下次微调和避雷内容透明地进入新计划；
2. 让用户在保存前知道“本次已带入什么、来自哪里”，并能逐条修改或删除；
3. 让确认后的记忆继续进入 Tony卡，而不是在 Tony卡页面静默读取所有历史；
4. 将用户可见品牌从“咋剪发”升级为“Tony宝”，将“沟通卡/理发师沟通卡”统一为“Tony卡”；
5. 在保存结果、生成计划和保存 Tony卡等关键反馈中使用克制的 Tony 人格；
6. 保留所有现有 IndexedDB 数据、图片 Blob、计划、历史记录和 Tony卡。

完成本轮后，用户应能明确回答：

- Tony 从哪一条历史中记住了什么；
- 哪些内容会带入这次计划和 Tony卡；
- 如何修改或删除这些内容；
- 修改计划记忆是否会反向改写历史（不会）；
- 旧数据是否仍在（必须仍在）。

## 2. 审计结论

### 2.1 当前已有能力

- `HaircutRecord` 已区分 `repeat / adjust / avoid`。
- `adjust` 记录保存 1—3 条 `adjustmentNotes`。
- `avoid` 记录同时保存原始 `avoidRules`，并生成独立的活动 `AvoidRule`。
- `repeat` 记录会生成 `StandardStyle`，可作为复刻计划的真实历史候选。
- 计划候选保存独立图片快照，删除原始参考后仍可使用。
- Tony卡已经会读取精选发型指南、个人偏好和活动避雷规则。
- 当前 IndexedDB 名为 `zajianfa-archive`，Dexie schema 为第 3 版。

### 2.2 当前缺口

- 所有活动避雷会在首次生成沟通卡时被静默合并，用户在建计划时看不到来源。
- `adjustmentNotes` 只显示在历史详情，不会进入下一次计划或 Tony卡。
- 满意经验只有“选历史记录作为候选”的间接复刻，没有明确的经验条目。
- 计划本身没有记忆快照；历史变化后无法解释某条沟通要求当初从何而来。
- 用户不能在计划层逐条修改或删除继承内容。
- 品牌名和“沟通卡”散落在页面标题、meta、导出文件、测试断言和用户文案中。

### 2.3 基线证据

审计前相关 Vitest 为 3 个测试文件、60 个测试全部通过。该结果只证明现有数据层和组件单测基线，不代表 V4 功能已经实现，也不能替代后续真实页面验收。

## 3. 范围边界

### 3.1 本轮要做

- 计划级记忆快照及 Dexie 向前兼容升级；
- 新建计划时的记忆建议、确认、编辑、删除和刷新恢复；
- 计划详情中的记忆来源展示；
- Tony卡只继承当前计划确认保留的记忆；
- 剪后保存后的结果归因反馈；
- 产品名配置常量及用户可见术语替换；
- 现有 Tony卡屏显和 PNG 导出的品牌文字升级；
- 对应单元测试、组件测试、Playwright 和真实页面截图。

### 3.2 本轮明确不做

- 不做 V4 第②步的 PWA、Service Worker、最后一张 Tony卡离线缓存和微信浏览器兜底；
- 不做第③步分享工作室、对比图、避雷海报、“帮我选”求助图和二维码落地页；
- 不做第④步匿名统计、邮箱登录和云备份；
- 不做第⑤步真实 AI、积分、次数包、支付或兑换码；
- 不做避雷区域点选打标；那属于 V4 第 6 节的独立能力；
- 不扩发型素材库，不恢复社区、投票、商家端或理发师端；
- 不实现基于自然语言的“智能冲突检测”，避免用关键词规则冒充 AI。

### 3.3 本轮暂不放二维码的原因

V4 要求分享图和导出图最终带品牌角标与二维码，但当前域名、ICP 和落地页尚未确定，分享工作室也属于第③步。第①步只给现有 Tony卡屏显和 PNG 加小型“Tony宝”品牌标识，不生成指向本地地址或临时地址的无效二维码。第③步在公开落地 URL 确定后统一实现二维码，避免重复设计和错误传播。

## 4. 方案选择

### 4.1 采用：计划级记忆快照

新增 `planMemoryItems` 表。新计划创建时，系统从历史生成建议；用户确认后把独立快照与计划一起保存。

优点：

- 来源透明，可逐条编辑和删除；
- 历史后来修改或删除，不会悄悄改变已保存计划；
- Tony卡可以稳定读取计划确认结果；
- 能明确区分“历史事实”和“本次采用的表达”。

代价：

- Dexie 增加一个表和一次 schema 升级；
- 计划保存事务需要同时写入候选与记忆条目；
- 删除计划时要同步删除该计划的记忆快照。

### 4.2 不采用：每次打开时实时聚合历史

实现较少，但计划内容会随历史变化，来源与保存时状态不可复现，不符合“来源可查、不黑箱”的要求。

### 4.3 不采用：把历史文字塞进候选备注或 Tony卡

改动最小，但会混淆候选来源、计划记忆和理发师表达三个职责，继续造成隐式继承，后续也难以安全编辑。

## 5. 数据设计

### 5.1 新增类型

```ts
type PlanMemoryKind = 'success' | 'adjustment' | 'avoid'

type PlanMemorySource =
  | 'repeat_record'
  | 'adjustment_note'
  | 'avoid_rule'
  | 'brief_priority'

interface PlanMemoryItem {
  readonly id: string
  readonly profileId: string
  readonly planId: string
  readonly order: number
  readonly kind: PlanMemoryKind
  readonly text: string
  readonly originalText: string
  readonly source: PlanMemorySource
  readonly sourceRecordId: string
  readonly sourceRecordDate: string
  readonly sourceLabel: string
  readonly createdAt: string
  readonly updatedAt: string
}
```

设计说明：

- `text` 是本次计划采用、允许用户修改的文字。
- `originalText` 保留生成快照时的历史原文，便于解释改动，不用于覆盖用户编辑。
- `sourceRecordId` 用于来源仍存在时跳回历史详情。
- `sourceRecordDate` 和 `sourceLabel` 是来源快照；即使原记录后来删除，计划仍可说明当时来源。
- 删除一条记忆采用真实删除，不增加隐藏的 `active` 状态；保存前建议尚未进入数据库。
- `order` 在同一计划和类别内稳定排序。

### 5.2 Dexie 升级

- 保持数据库名 `zajianfa-archive` 不变；这是数据身份，不因品牌改名。
- schema 从 v3 升到 v4，只新增：

```ts
planMemoryItems: 'id, planId, profileId, [planId+kind], [planId+order]'
```

- 不遍历、不重写任何现有表，不重新编码 Blob，不改变旧记录形状。
- 旧数据库打开后只创建新表；旧数据字节保持不变。
- 旧计划不自动补写记忆，以免发布后静默改变已有 Tony卡。

### 5.3 原子保存

`savePlanWithCandidates` 扩展为在同一 Dexie 事务中保存：

1. `HaircutPlan`；
2. `Candidate[]`；
3. `PlanMemoryItem[]`。

任一验证或写入失败，三类数据全部回滚。编辑计划时替换该计划的记忆集合；删除计划时一并删除记忆。删除历史记录不删除计划快照。

## 6. 记忆生成规则

### 6.1 生成时机

- 仅在“新建计划”首次加载完成后生成建议。
- 编辑已有计划时只读取已保存快照，不重新扫描历史。
- 用户在新建页修改或删除建议后，保存的是用户确认结果。
- 页面重载且计划尚未保存时可重新生成建议；不承诺保存未提交表单草稿。

### 6.2 排序与数量

分成两个展示组：

- “这次继续保持”：`success` 与 `adjustment` 合计最多 3 条；
- “这次一定避开”：`avoid` 最多 3 条。

统一规则：

1. 记录按日期、更新时间从新到旧；
2. 最近的明确反馈优先；
3. 完全相同的标准化文字去重，保留最新来源；
4. 超出上限的内容本轮不显示、不保存；
5. 不用 AI 改写用户原话。

### 6.3 微调经验

- 从最近的 `adjust` 记录读取 `adjustmentNotes`。
- 原文作为 `text` 和 `originalText`。
- 来源显示为“2026-08-12 · 上次微调 · 两侧留长一点”对应的记录名称和日期。

### 6.4 避雷经验

- 从仍为活动状态的 `AvoidRule` 读取，确保已失效规则不会进入新计划。
- 来源关联原始 `avoid` 记录。
- 不再在 Tony卡页面额外合并所有活动避雷；只有计划中确认保留的条目才能进入 Tony卡。

### 6.5 成功经验

从最近的 `repeat` 记录生成，按以下顺序取可靠事实：

1. 若该记录关联的原计划仍有 Tony卡，读取当时 Tony卡的 `topPriorities`，生成 `brief_priority` 条目；
2. 若没有可用 Tony卡重点，只生成一条“整体照上次的「发型名」复刻”，来源为 `repeat_record`；
3. 不根据照片、满意度或发型名推断长度、层次、脸型适配等不存在的事实。

### 6.6 复刻计划

复刻计划仍只允许一个活动标准发型候选。记忆建议与候选相互补充：候选提供真实照片快照，记忆提供用户确认过的沟通重点和避雷。不会因为选择复刻候选而跳过避雷建议。

### 6.7 冲突处理

本轮不尝试用自由文本自动判断“留长”和“剪短”等语义冲突。原因是现有数据尚未结构化到区域与问题类型，关键词判断会制造虚假确定性。

替代措施：

- 建计划时把“继续保持”和“一定避开”并列展示；
- Tony卡生成前再次展示两组内容；
- 用户可以直接修改或删除；
- 等避雷区域打标完成后，再基于明确区域和问题类型实现确定性冲突提示。

## 7. 页面与交互设计

### 7.1 新建计划页

在候选选择之前增加“本次已带入”区，仅在存在建议时显示。

每条包含：

- 类别：成功经验 / 下次微调 / 避雷；
- 可编辑文字输入框；
- 来源记录名称与日期；来源存在时可进入记录详情；
- “删除”按钮。

约束：

- 默认展开，让用户在第一次使用自动记忆时明确看见；
- 不使用开关、置信度或 AI 标签；
- 输入为空时不能保存该条，提示用户补充或删除；
- 每条最多 160 个字符，与现有微调和避雷长度一致；
- 删除后只影响本次计划，不改历史记录和活动避雷规则。

说明文案：

> Tony 从你的剪后记录里带来了这些经验。保存前都可以改，不会改动原记录。

此处是本屏唯一一次 Tony 人格出现。

### 7.2 编辑计划页

- 显示已保存的记忆快照，不重新生成。
- 允许编辑和删除。
- 本轮不提供“从最新历史重新同步”按钮，避免引入合并规则和覆盖风险。
- 编辑后更新 `text` 和 `updatedAt`，保留 `originalText` 与来源快照。

### 7.3 计划详情页

候选列表之前显示只读摘要：

- “这次继续保持”；
- “这次一定避开”；
- 每条显示来源日期和来源名称。

没有记忆快照的旧计划不显示空区块，也不提示数据缺失。

### 7.4 Tony卡编辑页

新建 Tony卡时：

- `success` 和 `adjustment` 依计划顺序进入“最在意”；
- `avoid` 进入“绝对不要”；
- 与精选发型指南合并后去重，并受各 3 条上限约束；
- 计划记忆优先于精选示例指南；
- 已保存的旧 Tony卡继续以自身内容为准，不被重新覆盖。

用户仍可在 Tony卡中修改最终表达。Tony卡的修改不反向改写计划记忆或历史，因为它是面向当次理发师的最终表达层。

### 7.5 剪后记录保存与归因

保存成功后先进入记录详情，并在详情顶部显示一次结果反馈：

- `repeat`：`Tony 记住了：这次的成功剪法已存档，下次一句话复刻。`
- `adjust`：`Tony 记住了：下次会带上你刚写的调整。`
- `avoid`：`这次的雷 Tony 记住了，下次替你挡。`

反馈只在刚保存后的导航中出现一次，刷新后不重复；历史结果区继续使用中性标题。这样既有结果归因，也不让人格每次打开页面都刷存在感。

### 7.6 Tony卡保存反馈

将“沟通卡已保存在当前设备”改为：

> Tony卡已保存在当前设备，到店直接打开。

这里是操作结果说明，不使用 Tony 第一人称，避免同屏出现第二个人格句。

## 8. 品牌与术语设计

### 8.1 配置常量

新增单一品牌配置模块，至少导出：

```ts
export const PRODUCT_NAME = 'Tony宝'
export const PRODUCT_PERSONA = 'Tony'
export const BARBER_CARD_NAME = 'Tony卡'
export const PRODUCT_PROMISE = '剪前帮你定，剪时替你说，剪后帮你记。'
```

Vue 页面、document title、Canvas 导出和测试从该模块读取；不建立可远程配置系统，不增加运行时复杂度。

### 8.2 用户可见替换范围

- 首页品牌名与承诺；
- App header、底部导航的可见品牌文案；
- 页面标题和 `document.title`；
- `index.html` 的 title、description、Open Graph 等已有 meta；
- 所有“沟通卡/理发师沟通卡”用户文案改为“Tony卡”；
- Tony卡屏显角标、PNG 标题、下载文件名、打印标题；
- 空状态、错误提示和测试断言中的旧品牌术语。

### 8.3 不替换的内部标识

为保护本机数据、路径兼容和部署稳定，本轮保留：

- npm 包名 `zajianfa`；
- IndexedDB 名 `zajianfa-archive`；
- 环境变量、E2E session key 和内部类名 `ZajianfaDb`；
- 现有路由 URL；
- Git 仓库名、历史提交和旧设计文档；
- 现有图标文件名 `zajianfa-scissors-*`。

验收中的“无咋剪发残留”指当前产品的用户可见运行界面、当前 meta 和新导出产物，不包含内部兼容键、历史文档、文件名和 Git 历史。

### 8.4 视觉品牌边界

本轮没有已确认的新 Logo 视觉方案，因此：

- 保留现有剪刀图标作为临时产品图标；
- 将其可访问名称和旁边文字升级为 Tony宝；
- Tony卡角落使用小型文字标识，不临时发明复杂 Logo；
- 商标核查未完成前，所有品牌文字通过常量引用，便于整体替换。

### 8.5 Tony 人格规则

- 只用于反馈、提醒和记忆说明；
- 按钮、表单 label、导航保持中性；
- 每屏最多一次；
- 成功场景可靠简短，失败场景克制共情；
- 不使用卖萌语气、感叹号堆叠、虚假智能或人格自夸；
- 不说“Tony 分析了照片”“Tony 判断你适合”，除非未来真实能力和证据存在。

## 9. 错误处理与边界状态

### 9.1 数据读取失败

- 历史读取失败时不生成空建议并假装没有历史；沿用档案读取错误状态，阻止保存来源不明的计划。
- 旧计划读取不到 `planMemoryItems` 时按“无快照旧计划”处理，不报错、不自动补写。

### 9.2 保存失败

- 计划、候选和记忆同一事务回滚；提示“保存失败，数据未写入，请重试”。
- 不出现计划保存成功但记忆丢失，或记忆保存成功但候选丢失的半成品状态。

### 9.3 来源后来被删除

- 计划仍显示来源快照文字和日期；
- 不再提供可点击链接，并说明“原记录已删除，保留当时快照”；
- 不删除、不改写计划记忆。

### 9.4 空历史

- 新用户或没有可继承内容时不显示“本次已带入”模块；
- 不生成通用建议，不用示例数据冒充个人记忆。

### 9.5 长文本与重复

- 单条限制 160 字；
- 保存前 trim；
- 相同类别中按 trim 后完全一致去重；
- 不做模糊相似度合并，以免误删用户表达差异。

## 10. 测试与验收设计

### 10.1 TDD 顺序

每项行为严格执行：先写失败测试并确认因缺少功能而失败，再写最小实现，再运行相关测试和完整回归。

### 10.2 数据层测试

- v3 数据库升级到 v4 后，旧 profile、plan、candidate、brief、record、photo Blob、avoid rule、standard style 字段与字节保持不变；
- 新建计划、候选和记忆原子保存；
- 编辑计划替换自己的记忆，不影响其他计划；
- 删除计划级联删除记忆；
- 删除历史记录保留计划记忆；
- 非本档案来源、空文本、超长文本、重复 id、错误顺序被拒绝；
- 本地备份导出/导入包含新表，旧备份仍可导入且记忆为空。

### 10.3 记忆规则单元测试

- 最近明确反馈优先；
- 微调原文继承；
- 仅活动避雷继承；
- 成功记录优先继承原 Tony卡重点；
- 没有 Tony卡时只生成可证实的复刻句；
- 完全相同文字去重；
- 两组分别遵守 3 条上限；
- 不生成 AI 推断或语义冲突结论。

### 10.4 组件与 Store 测试

- 新建计划可看到来源、编辑、删除并保存；
- 编辑旧计划不自动生成记忆；
- 编辑新计划读取已有快照；
- Tony卡优先使用计划记忆，不再扫描全局避雷；
- 已保存 Tony卡不被重新 hydrate 覆盖；
- 三种剪后结果出现正确的一次性归因反馈；
- 每个相关屏幕最多一次 Tony 人格。

### 10.5 品牌契约测试

- 没有 manifest 时不为了通过文字扫描新建空 manifest；PWA manifest 留到第②步。

### 10.6 Playwright 核心旅程

1. 建立档案；
2. 保存一次“就这样”、一次“有一点要改”、一次“别再这样”的真实记录；
3. 新建计划，核对建议顺序和来源；
4. 修改一条、删除一条并保存；
5. 刷新后确认计划快照不变；
6. 删除来源历史后确认计划快照仍在并标记来源已删除；
7. 生成 Tony卡，确认只使用保留条目；
8. 导出 Tony卡并核对品牌文字；
9. 旧数据库种子升级后走现有核心闭环；
10. 验证没有社区、投票、登录、支付或真实 AI 新入口。
